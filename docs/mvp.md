# BuildLog MVP 기획서

## 1. BuildLog란?

BuildLog는 공부한 내용, 앞으로 해야 할 일, 공부나 개발 중 만난 오류와 해결 방법을 한곳에 기록하는 웹 서비스입니다.

여러 사용자가 가입할 수 있고 컴퓨터와 휴대폰 브라우저에서 이용합니다. 각 기록은 기본적으로 작성자만 볼 수 있으며, 작성자가 원하면 로그인한 다른 사용자에게 공개할 수 있습니다.

## 2. MVP의 목표

첫 번째 버전은 다음 질문에 답할 수 있어야 합니다.

> 사용자가 공부 기록, 할 일, 오류 해결 기록을 한곳에 저장하고, 다시 찾고, 필요한 기록을 다른 사용자와 공유할 수 있는가?

## 3. 주요 사용자

- 오늘 공부하거나 작업한 내용을 기록하고 싶은 사람
- 공부 계획이나 프로젝트의 할 일을 관리하고 싶은 사람
- 오류와 해결 방법을 모아 두었다가 다시 찾고 싶은 사람
- 자신의 기록을 다른 사용자와 공유하고 싶은 사람

## 4. 첫 버전의 핵심 기능

### 4.1 회원

- 이메일, 비밀번호, 닉네임으로 회원가입합니다.
- 이메일과 비밀번호로 로그인합니다.
- 닉네임은 다른 사용자와 겹칠 수 없으며 나중에 변경할 수 있습니다.
- 사용자마다 비공개 기록이 분리됩니다.
- 로그인하지 않은 사람은 공개 기록을 포함한 기록 화면을 볼 수 없습니다.

### 4.2 공개와 비공개

- 공부 기록, 할 일, 오류 기록은 기본적으로 비공개입니다.
- 비공개 기록은 작성자만 볼 수 있습니다.
- 작성자는 자신의 기록을 공개 또는 비공개로 바꿀 수 있습니다.
- 공개 기록은 로그인한 다른 사용자가 볼 수 있습니다.

### 4.3 공부 기록

저장하는 정보는 다음과 같습니다.

- 제목: 1~100자
- 내용: 1~5,000자
- 공개 여부: 기본값은 비공개
- 작성 날짜와 시간: 만들 때 자동 저장

사용자는 자신의 공부 기록을 만들고, 목록과 상세 화면에서 읽고, 수정하고, 삭제할 수 있습니다. 제목과 내용으로 검색할 수 있으며 최근 기록부터 봅니다.

### 4.4 할 일

저장하는 정보는 다음과 같습니다.

- 제목: 1~100자
- 완료 여부: 미완료 또는 완료
- 공개 여부: 기본값은 비공개
- 완료 날짜와 시간: 완료로 바꿀 때 자동 저장

사용자는 할 일을 만들고, 수정하고, 삭제하고, 완료 또는 미완료로 바꿀 수 있습니다. 전체, 남은 일, 완료한 일로 나누어 봅니다.

### 4.5 오류 기록

저장하는 정보는 다음과 같습니다.

- 오류 제목: 1~100자
- 오류 내용: 1~5,000자
- 해결 방법: 해결 전에는 비워 둘 수 있으며 입력할 때는 1~5,000자
- 해결 여부: 미해결 또는 해결
- 공개 여부: 기본값은 비공개
- 해결 날짜와 시간: 해결로 바꿀 때 자동 저장

사용자는 미해결 오류를 먼저 저장하고 나중에 해결 방법을 추가할 수 있습니다. 해결 방법이 있어야 해결 상태로 바꿀 수 있습니다. 전체, 미해결, 해결로 나누어 보고 오류 제목과 내용으로 검색할 수 있습니다.

### 4.6 공개 기록과 검색

- 공개된 공부 기록, 할 일, 오류 기록을 한곳에서 봅니다.
- 기록 종류별로 나누어 봅니다.
- 공개 공부 기록은 제목과 내용, 공개 할 일은 제목, 공개 오류 기록은 오류 제목과 내용으로 검색합니다.
- 공개 기록은 최근에 작성한 기록부터 봅니다.

### 4.7 댓글과 좋아요

- 공개 공부 기록과 공개 오류 기록에서 댓글과 좋아요를 사용합니다.
- 공개 할 일에는 댓글과 좋아요를 제공하지 않습니다.
- 댓글은 1~500자입니다.
- 댓글 작성자는 자신의 댓글을 수정하고 삭제할 수 있습니다.
- 기록 작성자는 자신의 공개 기록에 달린 댓글을 삭제할 수 있습니다.
- 한 사용자는 같은 기록에 좋아요를 한 번만 남길 수 있고 다시 누르면 취소됩니다.

### 4.8 신고

- 로그인한 사용자는 공개 기록이나 댓글을 신고할 수 있습니다.
- 신고 이유는 1~500자입니다.
- 한 사용자는 같은 대상을 한 번만 신고할 수 있습니다.
- 운영자만 신고 내용을 확인합니다.
- 신고만으로 기록이나 댓글을 자동 삭제하지 않습니다.

## 5. 필요한 화면

- 회원가입 화면
- 로그인 화면
- 내 기록 홈 화면
- 계정 설정과 닉네임 변경 화면
- 공부 기록 목록·작성·상세·수정 화면
- 할 일 목록·작성·수정 화면
- 오류 기록 목록·작성·상세·수정 화면
- 공개 기록 목록·필터·검색 화면
- 공개 공부 기록과 오류 기록의 댓글·좋아요 영역
- 신고 입력 화면
- 운영자 신고 확인 화면

모든 주요 화면은 컴퓨터와 휴대폰 크기에 맞게 배치합니다.

## 6. 첫 버전에서 만들지 않는 기능

- 이메일 확인
- 비밀번호 찾기
- 할 일 마감일
- 할 일 중요도
- 내 할 일 검색
- 댓글 답글
- Supabase Auth
- 이미지와 파일 첨부
- 휴대폰에 설치하는 별도 앱

## 7. 개발 구성

- `frontend`: React와 Vite로 만드는 사용자 화면
- `backend`: Python FastAPI로 만드는 API, 로그인과 권한 처리
- `database`: SQLAlchemy 모델과 Alembic 변경 이력
- `docs`: 기획, 기능 동작과 개발 문서

실제 서비스 데이터는 Supabase Database의 PostgreSQL에 저장합니다. 로컬 개발과 자동 테스트에서는 SQLite를 사용합니다. React는 FastAPI API만 호출하며 Supabase 데이터베이스에 직접 연결하지 않습니다.

## 8. MVP 완료 기준

- 사용자가 회원가입하고 로그인할 수 있습니다.
- 각 사용자의 비공개 기록이 다른 사용자에게 노출되지 않습니다.
- 공부 기록을 만들고 검색·읽기·수정·삭제할 수 있습니다.
- 할 일을 만들고 완료·취소·필터·수정·삭제할 수 있습니다.
- 오류를 만들고 검색·해결·미해결 전환·수정·삭제할 수 있습니다.
- 기록을 공개 또는 비공개로 바꿀 수 있습니다.
- 공개 기록을 종류별로 보고 검색할 수 있습니다.
- 공개 공부 기록과 오류 기록에서 댓글과 좋아요를 사용할 수 있습니다.
- 공개 기록과 댓글을 신고할 수 있고 운영자만 신고 내용을 확인합니다.
- SQLite 자동 테스트가 통과합니다.
- Supabase PostgreSQL에서도 데이터 구조와 핵심 기능이 동작합니다.
- 컴퓨터와 휴대폰 브라우저에서 주요 기능을 사용할 수 있습니다.
